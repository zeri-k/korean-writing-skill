# 교정 행동 회귀 시험

실제 교정 과정에서 드러난 의미 누락, 조건 혼동과 완료 보고 오류를 다시 확인하는 자료다. `inputs.json`은 요청·원문·제공 근거를, `rubric.json`은 의미상 평가 기준을 담는다. 특정 문장과의 문자열 일치를 통과 기준으로 삼지 않는다.

1. 비교할 스킬의 수정 전·후 파일을 각각 보관하고 파일 해시, 모델·추론 설정과 실행 지시를 기록한다. 같은 입력과 실행 지시로 각 스킬을 별도 대화에서 실행한다. 새 사례는 기존 실패 문구를 바꾼 것뿐 아니라 다른 문서 유형과 작업 방식도 포함한다.
2. 교정자에게는 해당 스킬과 `inputs.json`만 제공한다. 평가 기준, 이전 출력과 예상 수정 방향은 제공하지 않는다. 결과는 항목별 `id`, `corrected_text`, `edits`와 `unresolved`를 포함하는 JSON으로 보관한다. `edits`에는 변경 전후, 변경 성격과 근거를 기록한다.
3. 별도 검토자에게 원문·근거와 함께 어느 스킬이 작성했는지 숨긴 출력을 제공한다. 요청 충족, 대상·행동·조건·범위·확인 정도, 근거 없는 추가·누락과 변경 보고의 정확성을 판단한다. 주 검토자는 실제 출력을 `rubric.json`과 대조하고, 검토자의 통과 보고만으로 결론을 확정하지 않는다.
4. 실제 출력에서 의미를 일부러 훼손한 별도 대조군도 섞어 검토가 문제를 발견하는지 확인한다. 실제 출력과 대조군의 대응표는 평가가 끝날 때까지 검토자에게 제공하지 않는다. 대조군의 변경 보고가 비어 있다는 등의 형식적 단서만으로 구별되지 않도록 한다.
5. 실패한 출력과 판정을 보존하고, 확인한 문제에 필요한 지침을 수정한 뒤 다시 시험한다. 최종 채택할 스킬은 내용을 고정한 상태에서 기존·새 사례를 복수의 독립된 대화로 실행해 재확인한다. 성공한 출력만 골라 집계하지 않으며 실행 횟수와 남은 실패를 함께 기록한다.

원문부터 제공 근거와 충돌할 수 있다. 요청 범위 안에서 근거에 맞게 정정하거나 해결할 수 없는 충돌을 미해결로 명시했는지 확인한다. 정당한 내용 정정, 요청한 요약에 따른 생략과 특정 상황만 다루는 설명을 단순한 원문 불일치나 범위 차이만으로 실패 처리하지 않는다. 평가 기준에도 자료로 확정할 수 없는 해석을 정답으로 넣지 않는다.

제공 자료로 알 수 없는 사실을 미해결로 남긴 결과와 교정이 만든 의미 문제를 해결하지 못한 결과를 구분한다. 교정의 요청 이행, 문체와 의미 보존도 따로 평가한다. 독립 검토자의 지적을 수용하거나 기각할 때는 실제 원문과 출력에 근거를 남긴다.

시험은 제공된 자료에 따른 교정 행동을 확인한다. 기술 문서 전체의 최신성, 명령의 실제 동작이나 다른 입력에서의 재현성을 보장하지 않는다. 파일 구조 검사와 실제 교정 결과의 평가를 별도로 보고한다. 개선을 주장할 때는 수정 전후의 실제 결과와 남은 실패를 함께 남긴다.
