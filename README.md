# Korean Writing Skill

문서의 의미와 기술적 정확성을 보존하며 명확한 한국어를 작성·교정하는 AI 에이전트 스킬입니다. 문서 작성, 번역, 요약과 상세 문장 교정에 사용합니다.

- 로컬 버전: **1.0.6** (이번 수정본은 미게시)
- 스킬 이름: `korean-writing`
- 라이선스: [MIT](LICENSE)

## 주요 기능

- 사실, 조건, 수치, 시제와 기술적 의미를 보존합니다.
- 대상과 수행 동작, 근거와 결과 사이의 관계를 명확히 설명합니다.
- 문서 목적과 예상 독자에 맞춰 표현, 설명 깊이와 약어 풀이를 조정합니다.
- 기술 용어는 해당 분야와 독자에게 통용되는 한국어, 영어 또는 한글 음역을 선택합니다.
- 권한 설명에는 권한 이름이나 식별자와 허용 동작을 명시하며, 확인되지 않은 권한 범위를 추정하지 않습니다.
- 과장과 불필요한 강조를 줄이고, 확인한 결과와 가능성·추정을 구분합니다.
- 사용자 수정본을 후속 교정의 기준으로 삼습니다.
- 작업에 필요한 참조 문서만 읽도록 구성되어 있습니다.

## 적용 범위

보고서, 기술 문서, PPT 문구와 발표 노트, 매뉴얼, 메일 등의 한국어 작성과 교정에 사용할 수 있습니다. 일반 질의응답이나 단순 맞춤법 확인에는 자동 적용하지 않도록 설명되어 있으며, 스킬을 명시하면 짧은 문장에도 적용할 수 있습니다. 자동 선택 여부는 사용하는 에이전트의 스킬 기능에 따라 달라집니다.

이 스킬을 사용할 때는 아래 작성 규칙을 따릅니다. 사용자가 요청한 방식이나 문서에 정해진 작성 규칙이 있으면 그것을 우선합니다. 기술·보안 분야의 예시는 해당 상황에서 어떻게 작성하는지 설명하기 위한 것이며, 예시에 등장하는 모든 표현을 다른 문서에서도 금지하거나 같은 형식을 요구하지는 않습니다.

## 별도로 지정하지 않았을 때의 작성 방식

- 설명문은 `~합니다/~습니다`, 규정과 지침은 `~한다`로 작성합니다. 절차는 실행할 행동을 설명하고, 부탁이나 권고를 의무로 바꾸지 않습니다.
- 누가 무엇을 하는지, 어떤 조건에서 가능한지, 결과가 다음 행동에 어떻게 사용되는지 문맥에 필요한 내용을 적습니다. 글을 짧게 쓰려고 필요한 설명을 생략하거나, 어려운 말을 다른 추상적인 말로 바꾸는 것만으로 설명을 끝내지 않습니다.
- 문장과 문단을 이어 읽으며 앞의 설명을 다음 문장이 어떻게 이어받는지 확인합니다. 내용에 따라 조건·예외·비교·이유·예시·후속 행동을 이어 설명합니다. 연결어 없이도 자연스러우면 그대로 쓰며, `~다`나 `~습니다`가 반복된다는 이유만으로 고치지 않습니다.
- 사실, 수치, 조건, 인용과 기술적 의미를 보존합니다. 가능성을 확인된 사실처럼 쓰지 않으며, 원문에 없는 정보를 만들어 넣지 않습니다.
- 독자에게 통용되는 용어를 사용합니다. 생소하거나 뜻이 모호한 용어는 실제 동작이나 역할을 설명합니다. 권한은 이름이나 식별자와 허용 동작을 명시합니다.
- 새 설명문에는 em dash와 en dash를 사용하지 않습니다. 괄호와 약어 풀이는 뜻을 이해하거나 화면·코드의 명칭과 대조하는 데 필요한 경우에 사용합니다.
- 보고서, PPT, 메일, 매뉴얼 등 문서 종류에 맞춰 작성합니다. 모든 문서의 분량이나 목차를 하나로 고정하지 않습니다. 제목이나 목록을 짧게 쓰더라도 뜻을 이해하는 데 필요한 조건은 남깁니다.

문체·표기·어휘의 자세한 규칙은 [공통 스타일](references/house-style.md), 생략된 설명과 문장·문단 연결을 검토하는 방법은 [문장 교정](references/prose.md), 문서 종류별 작성 방식은 [문서 형식](references/document-style.md)에서 확인할 수 있습니다. [SKILL.md](SKILL.md)는 작업에 필요한 참조 파일을 선택하는 방법을 안내합니다.

`실제`가 강조만 더하면 생략할 수 있지만, 모의훈련과 실제 사고를 구분할 때는 유지합니다. 약어 풀이도 예상 독자에게 필요한 경우에 추가합니다.

## 설치

### Codex의 프로젝트별 설치

사용할 프로젝트의 루트에서 다음 명령으로 `v1.0.4` 버전을 설치할 수 있습니다. Git이 필요하며, 설치 대상 폴더가 이미 있는 경우에는 기존 내용을 먼저 확인합니다.

```sh
git clone --branch v1.0.4 --depth 1 https://github.com/zeri-k/korean-writing-skill.git .agents/skills/korean-writing
```

설치 결과는 다음과 같습니다.

```text
프로젝트/
└── .agents/
    └── skills/
        └── korean-writing/
            ├── SKILL.md
            └── references/
```

Codex는 프로젝트의 `.agents/skills`에서 로컬 스킬을 탐색합니다. 새 스킬이 표시되지 않으면 Codex를 다시 시작할 수 있습니다. 사용자 전체에 설치하는 경로와 다른 설치 방법은 [공식 스킬 문서](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills)에서 확인할 수 있습니다.

다른 AI 에이전트에서 사용할 때는 해당 도구의 `SKILL.md` 지원 여부와 설치 경로를 확인합니다. 스킬 본문과 `references/` 폴더의 상대경로를 유지해야 합니다.

## 사용 예시

### 문장 교정

```text
$korean-writing
아래 문장을 검토해줘. 사실과 기술적 의미는 유지하고,
누가 무엇을 하는지, 어떤 조건에서 가능한지 설명이 빠진 곳은 보완하고,
뜻을 전달하는 데 필요하지 않은 강조는 줄여줘.
```

### 기술 문서 작성

```text
$korean-writing
아래 조사 결과를 개발자 대상 보고서로 작성해줘.
확인된 사실과 추정, 조치 제안과 적용 완료를 구분해줘.
```

### 사용자 수정본을 기준으로 재검토

```text
$korean-writing
내가 수정한 본문을 기준으로 문장 연결을 검토해줘.
수행 시점과 대상 범위를 유지하고, 추가 근거가 필요한 부분은 알려줘.
```

## 버전과 변경 제안

현재 파일의 버전은 [VERSION](VERSION)과 `SKILL.md`의 `metadata.version`에 기록합니다. 공개 배포할 때는 해당 버전의 Git 태그를 별도로 생성하며, 변경 이력은 [CHANGELOG.md](CHANGELOG.md)에 기록합니다. 위 설치 예시는 이번 로컬 수정 전 버전을 가리킵니다.

`KOREAN-WRITING-COMMON`은 공통 스타일 본문의 버전을 식별하며, 배포 버전과 별도로 관리합니다. 현재 값은 `1.0.2`입니다. 에이전트가 현재 대화에서 같은 식별자와 공통 스타일 본문을 함께 확인할 수 있으면 파일을 다시 읽지 않고 사용합니다. 이전에 읽었다는 기록만 남아 있거나 식별자가 다르면 파일을 다시 읽습니다. 공통 스타일 본문을 수정할 때는 식별자를 바꾸고 `SKILL.md`와 `house-style.md`에 같은 값을 기록합니다.

변경 제안에는 원문, 의도한 의미와 예상 독자, 문제가 된 표현을 포함하면 판단에 도움이 됩니다. 한 문서의 편집 선호를 모든 문서에 적용하는 규칙으로 확대하지 않는 것을 원칙으로 합니다.
