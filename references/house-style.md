# 한국어 공통 스타일

<!-- KOREAN-WRITING-COMMON: 1.0.0 -->

이 스킬을 적용하는 작업의 편집 기본값이다. 사용자 요청과 문서의 명시적 기준을 우선한다. 인용, 고유명사, 코드, 식별자, 원문 보존 구간과 교정 사례는 해당 작업의 보존 기준을 따른다.

## 문체와 의미

- 어휘, 표현과 문장 구성에 격식을 적용한다. 설명문은 `~합니다/~습니다`, 규정과 지침은 `~한다` 형태의 서술을 기본으로 한다. 격식을 이유로 불필요한 추상 명사나 장황한 명사구를 추가하지 않는다.
- `~하십시오`, `~하세요`, `~하라` 등의 명령조를 사용하지 않는다. 절차는 행동을 설명하고 요청은 정중하게 표현한다. 요청은 `검토를 부탁드립니다`, 의무는 `관리자는 실행 전에 승인을 받아야 합니다`처럼 강도를 구분한다. 문체를 정리하면서 요청과 권고를 의무로 강화하거나 원문의 의무를 약화하지 않는다.
- 사실, 조건, 수치와 기술적 의미를 보존한다. 가능성을 확인된 사실로 바꾸거나 확인된 사실을 불필요하게 가능성으로 낮추지 않는다. 수치의 대상과 단위, 비율의 분모를 확인할 수 있게 쓰고 근거가 없으면 추정하지 않는다.
- 내용 없는 문서 소개, 편집 해설과 장식적 구호를 추가하지 않는다. 필요한 요약, 출처와 해석의 한계는 유지한다. 불명확한 지시어는 실제 이름으로 정리하고 같은 대상을 임의의 유의어로 바꾸지 않는다.

## 표기

- 새 설명문에 em dash(U+2014)와 en dash(U+2013)를 사용하지 않는다. 문장 관계는 마침표, 쉼표, 괄호나 콜론으로 표현한다.
- 가운데점은 한 문장 안에서 대등한 단어를 짧게 나열할 때만 사용한다. 독립된 문장은 마침표로 끝낸다. 반복되는 나열 묶음은 조사와 접속 표현으로 풀거나 목록으로 나눈다.
- 필요한 약어 풀이와 용어 식별은 괄호로 설명한다. 첫 등장 예시는 `OWASP(Open Worldwide Application Security Project)`다. 전체 이름만으로 역할이 불분명하면 한국어 설명을 덧붙인다. 같은 뜻만 반복하는 병기는 줄이고 화면이나 코드 명칭과의 대조는 유지한다. 길거나 중첩되는 괄호는 별도 문장으로 정리한다.
- 금액과 인원은 값과 단위를 유지해 `6,000만`, `1억 4,700만`처럼 표기한다. 외국 기업과 서비스는 확인된 공식 로마자 표기를 기본으로 하고 공식 한글 명칭과 인용은 해당 작업의 기준을 따른다.

## 어휘와 명칭

- 설정은 `변경`, 내용은 `수정`, 토큰은 `생성`, 문서는 `작성`, 프로그램은 `개발` 또는 `구현`, 구성 요소는 `구성`으로 표현한다. 파일을 외부에서 받아 오는 동작은 `다운로드`, 코드와 프로그램을 동작시키는 행위는 `실행`으로 표현한다. 시험 실행이라는 의미가 있으면 유지한다.
- `나오다`, `돌려주다`, `빠지다`, `나가다`는 실제 동작에 맞춰 반환, 출력, 발견, 노출, 누락, 제거, 전달과 유출을 구분한다. 토큰 값의 존재와 유효성을 구별한다. 상태를 초래하는 `만들다`는 원인과 결과를 설명한다.
- 일반 상태의 `잔존`은 `남은`으로 정리하되 정확한 전문 용어는 유지한다. 미삭제나 미제거는 실제 삭제 상태가 확인된 경우에 사용한다. 일반 수량의 `여러`는 확인된 수나 범위로 설명하되 수량이 불명확하면 그 불명확성을 유지한다.
- `에러`와 `오류`는 문맥, 통용되는 표현과 제품의 표기에 따라 선택한다. `에러 페이지`, `에러 발생`, `에러 코드`처럼 `에러` 표기가 적절한 경우에는 유지한다. 어느 한쪽으로 일괄 치환하지 않으며 같은 대상을 설명할 때는 표기를 일관되게 사용한다.
- DB 문맥에서는 `쿼리`, 일반 설명의 `token`은 `토큰`을 기본으로 한다. `자원`은 실제 대상에 맞춰 리소스, 데이터나 API 엔드포인트로 구체화하고 절차 의미의 `프로세스`는 `절차`로 쓴다. 기술 식별자와 다른 의미의 전문 용어는 보존한다.
- 서비스 고객은 `이용자`, 임직원은 `사용자`, 피해가 확인된 사람은 `피해자`로 지칭한다. 다른 계정의 사람은 `다른 이용자`로 표현하고, 역할이 불명확하면 추정하지 않는다. 고정된 기술 표현은 유지한다.
- `저장소`를 단독으로 쓰지 않고 확인된 대상에 따라 Git repository, 형상관리시스템, 시크릿 관리 시스템, 키스토어, 데이터베이스, 파일 스토리지, 앱 로컬 스토리지, 브라우저 스토리지 또는 Terraform 상태 저장 백엔드로 구분한다. 구성을 모르면 무엇을 보관하는 위치인지 설명하며 Git이나 S3 사용을 추정하지 않는다.
- `~있으면`, 복수 접미사 `들`, `및`과 연결어는 형태만으로 금지하지 않는다. 단어의 일부를 어휘 오류로 오인하지 않고 조건, 수량과 기술적 차이를 보존한다. 어휘 변경 후 조사와 호응을 함께 확인한다.

짧은 응답에도 위 기준을 적용하되 불필요한 제목, 명사형 종결이나 검수 설명을 추가하지 않는다. 자신의 수정으로 발생한 오류는 바로 수정하고 미확인 사항을 확인한 것처럼 보고하지 않는다.
