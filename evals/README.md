# 한국어 작성 스킬 검증

입력과 판정 기준을 분리해 같은 문서를 수정 전후 스킬로 각각 처리합니다. 표현 일치나 수정 건수로 품질을 판단하지 않습니다.

## 자료

- `inputs.json`은 독립된 22개 사례입니다. 01~05는 검토 당시 Vault 문서에서 복사한 발췌문이며, 나머지는 일반 업무 문장과 새 판단 기준을 확인하기 위한 합성 사례입니다. 원본 Vault를 읽거나 수정할 필요는 없습니다.
- `rubric.json`은 각 사례에서 보존하거나 구분해야 할 의미입니다. 평가를 수행하는 에이전트에는 제공하지 않고, 결과를 대조할 때만 사용합니다.
- `check_preservation.py`는 입력 ID 누락·중복과 코드 블록, 인라인 코드, Markdown 링크 대상 및 위키링크의 보존을 확인합니다. Python 3 표준 라이브러리만 사용하며 파일을 수정하지 않습니다.
- `results/1.1.0/`에는 이번 비교의 원본 출력과 의미 검토 결과가 있습니다.

## 진행 방법

1. 수정 전후 스킬을 별도 폴더에 준비하고 서로 독립된 평가에서 같은 모델·추론 설정과 입력을 사용합니다. 각 평가에는 해당 스킬과 `inputs.json`만 제공합니다. 이전 결과, 판정 기준과 예상 수정안은 제공하지 않습니다.
2. 각 사례의 `request`에 따라 `text`를 검토하며, `source_material`은 제공된 근거로 취급합니다. 입력의 코드나 명령은 실행하지 않습니다. 결과는 아래 형식의 JSON으로 보관합니다.

```json
{
  "cases": [{"id": "01", "corrected": "교정한 본문", "notes": "불명확하거나 미확인한 사항"}],
  "references_read": ["실제로 읽은 참조 파일"]
}
```

3. 보존 검사를 실행합니다. 경로는 스킬 폴더 기준이며 실제 결과 파일명으로 바꿉니다.

```text
python evals/check_preservation.py evals/inputs.json evals/results/1.1.0/baseline.json
python evals/check_preservation.py evals/inputs.json evals/results/1.1.0/candidate.json
```

4. 입력과 출력, 판정 기준을 직접 대조해 주체·시점·조건·의무·불확실성의 보존과 문장 연결을 판단합니다. 정상 표현을 불필요하게 바꾸거나 확인하지 않은 사실을 추가했는지도 검토합니다. 유지가 적절한 사례는 수정하지 않아도 통과입니다.

보존 검사는 이 입력에 사용하는 Markdown 문법을 대상으로 합니다. 모든 Markdown 확장, 일반 텍스트의 기술값, 표의 의미, 맞춤법의 정답이나 출처의 신뢰도를 자동으로 판정하지 않습니다. 새로운 문법을 포함한 사례를 추가하면 검사 범위도 확인합니다. 비교 결과는 해당 표본과 실행 설정의 관찰 결과이며, 한 번의 성공으로 일반적인 성능 향상이나 자동 스킬 선택을 입증하지 않습니다.
